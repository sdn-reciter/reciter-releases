# Темы Reciter

Тема — это оформление приложения целиком: палитра, скругления, шрифты, фон,
форма панелей, плотность списка и то, какие элементы вообще показывать.

Тема — обычный JSON плюс, если нужно, картинки и шрифты рядом. Здесь описан
формат целиком: что можно задать и какие значения допустимы.

## Готовые темы

Готовая тема **«Шиноби. День»** лежит в этом репозитории — папка
[`themes/`](../themes). Ставить её вручную не нужно:

**Параметры → Темы** — карточки с миниатюрами. У тех тем, которых на устройстве
нет, есть кнопка загрузки: приложение скачает тему и добавит её в список.
Нажатие на карточку применяет тему.

Тем нет в самом приложении намеренно: каждая весит несколько мегабайт, и возить
их в установке у всех подряд незачем.

Эта же тема — рабочий пример формата: в ней задействовано почти всё, что
описано ниже. Как взять её за основу — в конце файла.

Что происходит дальше:

| В репозитории | В приложении |
|---|---|
| появилась новая тема | новая карточка с миниатюрой и кнопкой загрузки |
| тему поправили | у скачанной темы появляется кнопка **«Обновить тему»** |
| тему убрали | скачанная остаётся на устройстве и работает как обычно |

Обновление не приходит само: приложение сравнивает версии, когда вы открываете
экран тем, и предлагает кнопку. Применённая тема при обновлении остаётся
применённой.

Скачанная тема удаляется **с устройства**, а не насовсем: карточка вернётся с
кнопкой загрузки, и тему можно поставить снова. Насовсем удаляются только свои
темы — те, которых в репозитории нет.

Свою тему из файла — значок импорта в шапке того же экрана.

## Формат

Тема — папка с файлом `theme.json` и, если нужно, ресурсами рядом: картинка
фона и файлы шрифтов. Для обмена папка упаковывается в **ZIP**.

```
Моя тема.zip
├── theme.json      обязателен
├── bg.jpg          картинка фона (необязательно)
├── fontui.ttf      шрифт интерфейса (необязательно)
└── fontbook.ttf    шрифт текста книги (необязательно)
```

Голый `theme.json` тоже импортируется — просто без ресурсов.

**Импорт:** Параметры → Темы → значок импорта в шапке → выбрать `.zip` или
`.json`. Готовые темы из этого репозитория качаются прямо на том же экране.

Тема — это ТОЛЬКО данные, без исполняемого кода, поэтому импорт чужого файла
безопасен. Неизвестные поля игнорируются, значения вне диапазона заменяются
ближайшими допустимыми, а испорченная секция — значениями по умолчанию: тема от
новой версии приложения не сломает старую.

## Минимальная тема

Обязательно только `name`. Всё остальное необязательно.

```json
{
  "name": "Тёмный янтарь",
  "author": "sdn",
  "colors": { "background": "#1B1A17", "text": "#E8DCC8", "accent": "#D9A441" }
}
```

## Полный пример

```json
{
  "name": "Тёмный янтарь",
  "author": "sdn",
  "designSystem": "classic",

  "colors": { "background": "#1B1A17", "text": "#E8DCC8", "accent": "#D9A441" },
  "reader": { "background": "#211F1B", "text": "#E3D6BE", "accent": "#D9A441" },

  "shapes": { "extraSmall": 6, "small": 10, "medium": 16, "large": 22, "extraLarge": 28 },

  "typography": {
    "fontFamily": "serif",
    "scale": 1.05,
    "fontFile": "fontui.ttf",
    "readerFontFile": "fontbook.ttf"
  },

  "layout": { "gridMinSize": 110, "gridSpacing": 10, "contentPadding": 12 },

  "controls": { "sliderThumb": "bar", "sliderTrackHeight": 4 },

  "bars": { "shape": "wavy", "curveHeight": 14, "opacity": 0.9, "inset": 12 },
  "topBar": { "shape": "rounded", "curveHeight": 12, "opacity": 1.0 },

  "gradients": { "accent": true, "accentTo": "#8A5E1F", "angle": 90, "bars": false },

  "surfaces": { "opacity": 0.85 },
  "notifications": { "opacity": 0.9, "inset": 16, "contentInsetX": 0.11, "contentInsetY": 10 },

  "visibility": {
    "showBookTitles": true,
    "showBookAuthors": true,
    "showProgressBadge": true,
    "showReaderProgress": true,
    "showAnnouncements": true
  },

  "elements": {
    "TOP_BAR":    { "variant": "large" },
    "TABS":       { "variant": "underline" },
    "READER_BAR": { "variant": "pill" },
    "FILTERS":    { "hidden": true }
  },

  "customElements": [
    { "id": "e1", "slot": "reader_top_bar", "function": "bookmark" }
  ],

  "background": {
    "type": "gradient",
    "colors": ["#1B1A17", "#3A2E1F"],
    "angle": 45,
    "image": "bg.jpg",
    "imageAlpha": 0.25
  }
}
```

## Типы значений

| Тип | Запись | Примечание |
|---|---|---|
| цвет | `"#RRGGBB"` или `"#AARRGGBB"` | полностью прозрачный цвет считается «не задано» |
| dp | целое число | экранная единица Android |
| доля | число `0…1` | `0.9` = 90 % |
| градусы | целое `0…360` | 0 — слева направо, 90 — сверху вниз |
| набор | строка из списка | неизвестное значение → первый вариант |

## Параметры

### Дизайн-система

| Ключ | Тип | Значения | По умолчанию |
|---|---|---|---|
| `designSystem` | набор | `classic`, `brutalist` | `classic` |

`brutalist` — моноширинный шрифт, нулевые скругления, жирные рамки, острый
бегунок. Он перебивает выбор дизайн-системы в настройках приложения и форму
бегунка из `controls.sliderThumb`.

### Цвета приложения — `colors`

| Ключ | Тип | По умолчанию | Что красит |
|---|---|---|---|
| `background` | цвет | `#FFFFFFFF` | фон экранов |
| `text` | цвет | `#FF1A1A1A` | текст интерфейса |
| `accent` | цвет | `#FF6750A4` | кнопки, выделение, прогресс |

Остальная палитра (контейнеры, контуры, поверхности) выводится из этих трёх.

### Цвета читалки — `reader`

Те же три ключа. Действуют на странице книги: фон, текст, акцент. Если секции
нет — берутся значения из `colors`.

### Скругления — `shapes`

Все в dp, диапазон `0…40` (`extraLarge` — до 64).

| Ключ | По умолчанию | Где видно |
|---|---|---|
| `extraSmall` | 6 | тонкие индикаторы |
| `small` | 10 | чипы, кнопки |
| `medium` | 16 | карточки |
| `large` | 22 | плашки, FAB |
| `extraLarge` | 28 | круглые кнопки, шторки |

Для брутализма обычно ставят все нули.

### Типографика — `typography`

| Ключ | Тип | Значения | По умолчанию |
|---|---|---|---|
| `fontFamily` | набор | `system`, `sans`, `serif`, `mono` | `system` |
| `scale` | доля | `0.7…1.6` | `1.0` |
| `fontFile` | имя файла | `.ttf` / `.otf` рядом с темой | — |
| `readerFontFile` | имя файла | `.ttf` / `.otf` рядом с темой | — |

`scale` умножает штатную шкалу, поэтому иерархия заголовков сохраняется.

Слотов шрифта два: `fontFile` — интерфейс, `readerFontFile` — текст книги.
Разделение не формальное: декоративный шрифт хорош в заголовках и нечитаем на
странице книги. Файл шрифта, выбранный пользователем в параметрах приложения,
важнее шрифта темы.

### Раскладка библиотеки — `layout`

| Ключ | Тип | Диапазон | По умолчанию |
|---|---|---|---|
| `gridMinSize` | dp | 70…220 | 110 |
| `gridSpacing` | dp | 0…32 | 10 |
| `contentPadding` | dp | 0…32 | 12 |

Размер ячейки задаётся минимальной шириной, а не числом колонок: на планшете и
в ландшафте колонок становится больше, а обложки не растягиваются.

`contentPadding` — это поля списка книг со всех сторон, в том числе **зазор
между шапкой библиотеки и содержимым**. Он одинаков на всех вкладках, поэтому
подгонять его достаточно один раз: и там, где под вкладками есть ряд фильтров,
и там, где его нет.

### Элементы управления — `controls`

| Ключ | Тип | Значения | По умолчанию |
|---|---|---|---|
| `sliderThumb` | набор | `bar`, `round`, `square` | `bar` |
| `sliderTrackHeight` | dp | 2…16 | 4 |

`bar` — штатный вид Material, вертикальная плашка. При `designSystem:
"brutalist"` бегунок всегда острый, значение игнорируется.

Форма распространяется на ВСЕ ползунки: и на перемотку книги в панели
управления, и на настройки. Разного вида на разных экранах не бывает.

### Нижняя панель управления — `bars`

| Ключ | Тип | Значения | По умолчанию |
|---|---|---|---|
| `shape` | набор | `flat`, `rounded`, `wavy`, `notched` | `flat` |
| `curveHeight` | dp | 0…40 | 12 |
| `opacity` | доля | 0.2…1 | 1.0 |
| `inset` | dp | 0…32 | 12 |

`shape` задаёт форму ВЕРХНЕЙ кромки панели: ровная, скруглённые углы, волна во
всю ширину, полукруглый вырез под центральную кнопку. `curveHeight` — амплитуда
волны или глубина выреза; при `flat` не действует. `inset` — отступ панели от
краёв, действует у видов `floating` и `pill` (см. «Виды элементов»).

Прижата панель к низу или оторвана от краёв — задаёт не `bars`, а вид элемента
`READER_BAR`.

### Шапка — `topBar`

| Ключ | Тип | Значения | По умолчанию |
|---|---|---|---|
| `shape` | набор | `flat`, `rounded`, `wavy` | `flat` |
| `curveHeight` | dp | 0…40 | 12 |
| `opacity` | доля | 0.2…1 | 1.0 |

Строка фильтров по статусу рисуется ВНУТРИ шапки, поэтому фигурная кромка
проходит под ней. Раньше фильтры стояли отдельным рядом ниже и обрезали волну
прямой линией.

У шапки фигурная кромка НИЖНЯЯ. Выреза (`notched`) здесь нет: он рассчитан на
выступающую кнопку внизу экрана. Волна сверху и снизу одновременно смотрится
как ошибка вёрстки — параметры шапки и панели разведены намеренно.

### Градиенты — `gradients`

| Ключ | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `accent` | да/нет | `false` | градиент на акцентных элементах: кнопка воспроизведения, FAB, основные кнопки |
| `accentTo` | цвет | акцент со сдвигом яркости | второй цвет акцентного градиента |
| `angle` | градусы | 90 | направление обоих градиентов |
| `bars` | да/нет | `false` | градиент на панелях и шапке |

Если `accentTo` не задан, берётся акцент, сдвинутый по светлоте примерно на
25 %, — иначе «градиент» из акцента в акцент не виден.

### Поверхности — `surfaces`

| Ключ | Тип | Диапазон | По умолчанию |
|---|---|---|---|
| `opacity` | доля | 0.3…1 | 1.0 |

Прозрачность карточек и плашек. Нужна темам с картинкой на фоне: сплошные
карточки закрывают её целиком. Обложки книг остаются непрозрачными.

### Уведомления — `notifications`

| Ключ | Тип | Диапазон | По умолчанию |
|---|---|---|---|
| `opacity` | доля | 0.4…1 | 1.0 |
| `inset` | dp | 0…32 | 16 |
| `contentInsetX` | доля | 0…0.35 | 0.11 |
| `contentInsetY` | dp | 0…40 | 10 |

Действуют на все плашки сразу: статус операции, загрузка, удаление,
синхронизация, перевод, обновление, объявления.

`inset` — отступ плашки от краёв ЭКРАНА. `contentInsetX` и `contentInsetY` —
поля ВНУТРИ плашки, под рамку своей картинки (`images.notification`); без
картинки они ничего не делают.

Нарисованная плашка почти никогда не прямоугольная: у свитка по краям валики, у
пергамента — рваная кромка. Текст, кнопка закрытия и полоса прогресса, прижатые
к краю, наезжают на них. Сколько занимает рамка, знает только автор картинки —
поэтому это параметр темы.

Ширина — доля, а не dp: картинка растягивается по ширине плашки, значит на
широком экране её рамка шире. Высота в dp: плашка тянется за содержимым, и доли
считать не от чего.

Как подобрать: посмотрите, где на картинке кончается «поле для текста». У
свитка темы-примера валики занимают по десятой доле ширины, и стоит `0.14` —
запас, чтобы крестик закрытия не касался валика.

### Видимость элементов — `visibility`

Все — `true` по умолчанию.

| Ключ | Что скрывает |
|---|---|
| `showBookTitles` | названия под обложками |
| `showBookAuthors` | авторов под обложками |
| `showProgressBadge` | значок прогресса на обложке |
| `showReaderProgress` | полосу прогресса в читалке |
| `showAnnouncements` | плашки объявлений |

Вкладки и строка фильтров скрываются не здесь, а через `elements`
(`"TABS": { "hidden": true }`) — см. «Виды элементов».

Блокирующие объявления не скрываются: это единственный способ сообщить о
неработающей версии.

### Виды элементов — `elements`

Секции выше задают ЗНАЧЕНИЯ (цвет, размер, прозрачность). `elements` задаёт, во
что элемент интерфейса превращён, скрыт ли он и что делает по нажатию. Это
разная вёрстка при тех же настройках, поэтому и раздел отдельный.

Записывать нужно только отличия от штатного вида — нетронутые элементы в файл не
попадают.

```json
"elements": {
  "TOP_BAR": { "variant": "large", "action": "open_settings" },
  "TABS":    { "hidden": true }
}
```

| Ключ | Тип | Значения |
|---|---|---|
| `variant` | набор | зависит от элемента, см. таблицу ниже |
| `hidden` | да/нет | только у элементов, помеченных «можно скрыть» |
| `action` | набор | `none`, `open_settings`, `back_to_library`, `back_to_book` |
| `order` | число | место блока внутри своей зоны, с нуля |
| `corner` | набор | `bottom_end`, `bottom_center`, `bottom_start` — только у `FAB` |

| Элемент | Что это | Виды (первый — штатный) | Можно скрыть |
|---|---|---|---|
| `TOP_BAR` | шапка | `bar`, `large`, `compact` | нет |
| `TABS` | вкладки библиотеки | `chips`, `underline`, `segmented` | да |
| `FILTERS` | фильтры по статусу | — | да |
| `READER_PROGRESS` | полоса прогресса в читалке | — | нет |
| `READER_CONTROLS` | кнопки воспроизведения | — | нет |
| `BOOK_GRID` | сетка обложек | — | нет |
| `SECTION_HEADER` | заголовок секции библиотеки | `header_plain`, `header_accent`, `header_divider` | нет |
| `BOOK_CARD` | карточка книги | `elevated`, `outlined`, `flat` | нет |
| `EMPTY_STATE` | пустая библиотека | `with_icon`, `small_icon`, `no_icon` | нет |
| `FAB` | кнопка добавления | `extended`, `circle`, `mini` | нет |
| `READER_PAGE` | страница книги | — | нет |
| `READER_BAR` | панель управления | `docked`, `floating`, `pill` | нет |
| `BANNERS` | плашки уведомлений | `card`, `strip`, `plain` | нет |
| `DIALOG` | диалоги | `dialog_tonal`, `dialog_flat`, `dialog_outlined` | нет |
| `GROUP_CARD` | карточка полки, серии, автора | `outlined`, `elevated`, `flat` | нет |
| `STAT_CARD` | плитка статистики | `outlined`, `elevated`, `flat` | нет |
| `SETTINGS_CONTROLS` | ползунки и переключатели | — | нет |
| `SHEET` | шторка снизу (параметры, оглавление, поиск) | `with_handle`, `no_handle` | нет |
| `THEME_CARD` | карточка темы в галерее | `elevated`, `outlined`, `flat` | нет |

Скрыть можно только то, без чего приложением всё ещё можно пользоваться: шапка,
кнопка добавления и панель управления не скрываются намеренно — из такой темы не
было бы выхода.

Порядок видов в таблице значим: ПЕРВЫЙ — штатный вид этого элемента. У обложки
книги это `elevated` (она живёт с тенью), у карточек-строк — `outlined` (они
живут с рамкой), поэтому одно и то же слово в разных строках стоит на разных
местах.

Неизвестный элемент, чужой для него вид и `hidden` у нескрываемого элемента
игнорируются: файл из будущей версии не сломает вид в старой.

#### Компоновка

Блоки одной ЗОНЫ можно менять местами полем `order` (с нуля, по порядку сверху
вниз):

| Зона | Блоки |
|---|---|
| шапка библиотеки | `TABS`, `FILTERS` |
| панель управления читалки | `READER_PROGRESS`, `READER_CONTROLS` |

```json
"elements": {
  "FILTERS": { "order": 0 },
  "TABS":    { "order": 1 },
  "FAB":     { "corner": "bottom_center" }
}
```

Накладная кнопка добавления переставляется не порядком, а углом (`corner`).

Свободного размещения по координатам нет намеренно: блок, поставленный в
произвольную точку, на чужом экране уезжает под вырез камеры или за край.
Внутри зоны любой порядок остаётся рабочей вёрсткой.

### Свободная раскладка — `blocks`

Экран собирается из блоков: каждый блок — элемент с координатами и размером
внутри рамки телефона. Размер рамки задаёт сама тема — `canvasWidth` и
`canvasHeight` (dp) в корне файла; без них берётся **360 × 720 dp**. Указывайте
тот размер, под который считали координаты.

**Как раскладка ведёт себя на другом экране.** По горизонтали координаты и
ширины пересчитываются в долях от `canvasWidth`: блок, поставленный у правого
края, останется у края на телефоне любой ширины. По вертикали значения
остаются в dp как заданы — иначе текст и значки растягивались бы вместе с
экраном.

В файле темы секции `blocks` может не быть вовсе: тогда работает штатная
вёрстка, и всё выше (виды, зоны, скрытие) действует как обычно.

```json
"canvasWidth": 360,
"canvasHeight": 720,
"blocks": {
  "LIBRARY": [
    { "element": "TOP_BAR",   "x": 0,   "y": 0,   "w": 360, "h": 96 },
    { "element": "BOOK_GRID", "x": 0,   "y": 96,  "w": 360, "h": 280 },
    { "element": "FAB",       "x": 192, "y": 640, "w": 160, "h": 56 }
  ]
}
```

| Ключ | Значение |
|---|---|
| `element` | имя элемента из таблицы выше; должен принадлежать этому экрану |
| `x`, `y` | левый верхний угол, dp от левого верхнего угла экрана |
| `w`, `h` | размер, dp; меньше 24 не бывает |

Координаты — в dp, а не в пикселях: тема переносится между экранами разной
плотности, и абсолютные пиксели сломали бы её на первом же чужом телефоне.
Значения приводятся к рамке телефона при загрузке. Кратные 8 dp удобнее: на
такой шаг рассчитаны отступы штатной вёрстки.

Один элемент можно поставить на экран только один раз: два одинаковых блока
означали бы две шапки или две сетки книг.

#### Панели собираются из частей

Шапка библиотеки, шапка читалки и панель управления разбираются на части —
логотип, название главы, счётчик страниц и каждая кнопка. Часть кладётся ПОВЕРХ
своей панели, её координаты считаются относительно панели автоматически.

| Панель | Части |
|---|---|
| `TOP_BAR` (библиотека) | `LOGO`, `SEARCH_BUTTON`, `SORT_BUTTON`, `VIEW_BUTTON`, `ACCOUNT_BUTTON` |
| `READER_TOP_BAR` | `BACK_BUTTON`, `CHAPTER_TITLE`, `READER_SEARCH_BUTTON`, `BOOKMARK_BUTTON`, `READER_SETTINGS_BUTTON` |
| `READER_BAR` | `READER_PROGRESS`, `PROGRESS_TEXT`, `PREV_BUTTON`, `PLAY_BUTTON`, `NEXT_BUTTON`, `TIMER_BUTTON`, `TOC_BUTTON` |

Часть, которую не поставили, не рисуется — так из панели убирают лишнее. Пока не
поставлена ни одна часть, панель работает в обычном виде.

```json
"blocks": {
  "LIBRARY": [
    { "element": "TOP_BAR",        "x": 0,   "y": 0,  "w": 360, "h": 56 },
    { "element": "LOGO",           "x": 16,  "y": 8,  "w": 160, "h": 40 },
    { "element": "ACCOUNT_BUTTON", "x": 264, "y": 8,  "w": 40,  "h": 40 },
    { "element": "SEARCH_BUTTON",  "x": 312, "y": 8,  "w": 40,  "h": 40 }
  ]
}
```

### Свои кнопки — `customElements`

Тема может ДОБАВИТЬ кнопку. Не нарисовать произвольный элемент — тема остаётся
данными, а не кодом, — а поставить кнопку на функцию, которую приложение уже
умеет.

```json
"customElements": [
  { "id": "e1", "slot": "reader_top_bar", "function": "bookmark" },
  { "id": "e2", "slot": "reader_bar",     "function": "sleep_timer" }
]
```

| Ключ | Значения |
|---|---|
| `id` | любая строка, уникальная в пределах темы |
| `slot` | `library_top_bar`, `reader_top_bar`, `reader_bar` |
| `function` | `search`, `bookmark`, `settings`, `sleep_timer`, `back`, `themes` |

Какие функции есть, решает экран: «поиск» в библиотеке — это строка поиска, а в
читалке — поиск по книге. Функции, которой на экране нет (закладка в
библиотеке), кнопка не рисуется — тема не ломается, просто кнопки не будет.

Свободного размещения по координатам нет намеренно: кнопка, уехавшая под вырез
камеры на чужом телефоне, — это сломанная тема, а не гибкая.

### Фон приложения — `background`

| Ключ | Тип | Значения | По умолчанию |
|---|---|---|---|
| `type` | набор | `solid`, `gradient`, `image` | `solid` |
| `colors` | список цветов | ≥ 2 для градиента | — |
| `angle` | градусы | 0…360 | 90 |
| `image` | имя файла | картинка рядом с темой | — |
| `imageAlpha` | доля | 0…1 | 0.25 |

При `solid` фон берётся из `colors.background`. При `gradient` нужны минимум два
цвета в `colors`. При `image` картинка рисуется поверх заливки с прозрачностью
`imageAlpha` — полностью непрозрачная картинка делает текст нечитаемым.

## Ограничения

- Шрифты — только `.ttf` и `.otf`; файл проверяется при импорте, битый
  отбрасывается.
- Архив темы при распаковке ограничен по объёму, пути внутри архива
  игнорируются — берутся только имена файлов.
- Своя тема перебивает штатную целиком. Выбор штатной темы в параметрах
  приложения снимает пользовательскую.

### Свои картинки — `images`

Кроме фона приложения тема может подложить собственную картинку под отдельные
места. Файлы лежат в папке темы рядом с `theme.json`, в секции указывается
только имя файла:

```json
"images": {
  "appBackground":    "backdrop.jpg",
  "readerBackground": "parchment.jpg",
  "notification":     "scroll.png",
  "topBar":           "header.png",
  "bottomBar":        "player.png"
}
```

| Слот | Куда подставляется | Пропорции исходника |
|---|---|---|
| `appBackground` | фон всего приложения (то же, что `background.image`) | вертикальные, 9:20 |
| `readerBackground` | подложка страницы книги — «пергамент» | вертикальные, 9:20 |
| `topBar` | фон верхней панели | широкая полоса, ~18:5 |
| `bottomBar` | фон нижней панели читалки | широкая полоса, ~3:1 |
| `notification` | подложка всплывающих плашек — «свиток» | широкая полоса, ~10:3 |
| `sheet` | подложка выдвижной шторки параметров | вертикальные, 9:20 |
| `logo` | знак вместо названия приложения в шапке библиотеки | широкие, ~3:1 |
| `preview` | миниатюра темы в списке тем | квадратные, ~1:1 |

Шторке дайте картинку **во весь экран**, а не панель по её высоте: шторку тянут
вверх, и панельная картинка заканчивается на середине движения.

`preview` — единственный слот, который нигде в приложении не рисуется: это
обложка темы для карточки в списке, а не её часть. Не задан — карточка
собирается сама из фона, полос панелей и листа страницы. Задан — показывается
только он, поэтому это может быть просто иллюстрация в духе темы. Размер
карточки около 150×150 dp: мелкие детали и надписи там не читаются.

Слоты `card` и `emptyState` в файле темы разбираются, но пока ни один экран их
не показывает — задавать их рано.

Картинка растягивается на всю область слота по принципу «покрыть»: лишнее
уходит за край, пропорции не искажаются. Отсюда три практических правила:

- **Пропорции исходника должны совпадать с местом.** Альбомная картинка на
  вертикальном экране теряет около двух третей ширины — остаётся середина.
- **Середина должна быть спокойной.** Поверх подложки идёт содержимое: текст
  книги, названия, кнопки. Рисунок и надписи держите у краёв и делайте бледными.
- **Края обрезаются непредсказуемо.** Рваная кромка, рамка или подпись по краю
  либо срежется, либо ляжет на первую строку текста. Для подложки страницы
  лучше брать чистую внутренность листа, а не лист целиком.

Исключение — панели: у них обрезка прижата к той стороне, где нарисована
кромка. `topBar` прижимается к нижнему краю картинки, `bottomBar` — к верхнему.
Так обугленная или резная кромка панели остаётся видна целиком и на низкой
панели (в библиотеке высота шапки зависит от того, сколько рядов фильтров
показано). Обратную сторону картинки, наоборот, срежет — держите там фактуру,
а не рисунок.

Подложка панели обрезается формой панели: при скруглённой или фигурной кромке
углы картинки срежутся вместе с ней.

**Светлое и тёмное.** Подложки панелей, шторки и плашек лежат под текстом
интерфейса — он берёт цвет из `colors.text`. У тёмной темы он светлый, поэтому
светлая бумага под ним не читается: эти подложки делайте тёмными. Светлая
подложка уместна только у `readerBackground` — там цвет текста берётся из
`reader.text`.

Слот, которого нет в секции, рисуется как обычно — можно задать одну подложку
и не трогать остальные. Неизвестные слоты игнорируются, путь в имени файла не
допускается (только имя рядом с `theme.json`).

Формат — `png` или `jpg`. `png` с прозрачностью нужен свитку, `jpg` заметно
легче для крупных фонов. Держите разрешение соразмерным экрану (по ширине
1000–1500 пикселей): картинки темы лежат в памяти распакованными, и лишние
пиксели стоят мегабайтов.

### Свои значки кнопок — `icons`

Тема может подменить значки кнопок своими картинками. Как и `images`, значение —
имя файла рядом с `theme.json`:

```json
"icons": {
  "search":   "ic_search.png",
  "play":     "ic_play.png",
  "settings": "ic_settings.png"
}
```

| Слот | Кнопка |
|---|---|
| `search` `filter` `viewMode` `account` `addBook` | библиотека: поиск, фильтр, вид списка, аккаунт, «Добавить книгу» |
| `back` `bookmark` `settings` | читалка, верхняя панель |
| `play` `pause` `prev` `next` `timer` `contents` | читалка, нижняя панель |

**Цвет задаёте вы сами.** Значок рисуется как есть и не перекрашивается —
оранжевая спираль останется оранжевой. Отсюда требование: один и тот же файл
должен читаться на всех панелях, где эта кнопка встречается. Значки нижней
панели читалки лежат на её подложке, а значки библиотеки — на своей: если эти
подложки у темы разной светлоты, значок придётся подбирать под обе.

**Фон — прозрачный.** Значок на белом квадрате будет виден белым квадратом.

Размер — квадрат, 256 × 256 достаточно: на кнопке значок занимает 24 dp, то есть
96 пикселей даже на самом плотном экране. Оставьте вокруг рисунка поле примерно
в шестую часть стороны — вплотную к краю значок выглядит крупнее соседних
штатных и упирается в границу кнопки. Картинка вписывается целиком в то же
место, что занимает штатная иконка, поэтому кнопки не «прыгают».

Слот без своего файла остаётся со штатной иконкой — можно подменить одну кнопку
и не трогать остальные.

### Чего тема пока НЕ умеет

Чтобы не тратить время на подбор несуществующих ключей — вот граница
возможностей на сегодня:

- **Одна палитра на приложение.** Есть фон, текст и акцент (плюс отдельная
  тройка для читалки). Отдельного цвета у карточек, плашек, прогресс-баров и
  бейджей нет — они выводятся из этих трёх.
- **Свой фон — у приложения, читалки, панелей, плашек и шторки параметров.**
  Отдельной подложки для галереи и экрана статистики нет.
- **Значок можно подменить только у кнопок из списка `icons`.** Пункты меню,
  чипы фильтров и служебные значки остаются штатными.
- **Раскладка применяется только к панелям.** Секция `blocks` реально влияет на
  верхнюю панель библиотеки и обе панели читалки — их можно собрать из частей.
  Расположение сетки обложек, карточек и кнопки добавления тема не задаёт.
- **Нижней навигации в приложении нет.** Разделы переключаются вкладками
  сверху, поэтому оформить панель вкладок снизу нечем.
- **Тема не меняет поведение** — только вид. Скрыть элемент можно, добавить
  новый экран или новое действие нельзя; кнопки из `customElements` выбираются
  из закрытого списка того, что приложение уже умеет.

## С чего начать, если лень с нуля

Возьмите **«Шиноби. День»** и правьте её — это рабочий пример всего, что
описано выше, а не заготовка. Архив лежит в [`themes/`](../themes).

```
shinobi-day.zip
├── theme.json      палитра, формы, шрифты, раскладка, ссылки на файлы
├── backdrop.jpg    фон приложения
├── parchment.jpg   страница книги
├── topbar.jpg      шапка
├── bottombar.jpg   панель управления
├── sheet.jpg       подложка шторки параметров
├── scroll.png      подложка плашки уведомления
├── logo.png        знак в шапке библиотеки
├── preview.jpg     обложка темы для карточки в списке
└── ic_*.png        14 значков кнопок
```

Что в ней видно на практике: светлая палитра со своей палитрой читалки,
акцентный градиент, картинки под каждой панелью с декоративной кромкой,
собственные значки, готовая обложка. Порядок работы:

1. Распакуйте архив в папку.
2. Откройте `theme.json`, поменяйте цвета и **обязательно** `name` — тема с
   чужим именем встанет рядом с оригиналом, и отличить их в списке будет нечем.
3. Замените картинки своими, оставив имена файлов, либо пропишите новые имена в
   секциях `images` и `icons`.
4. Запакуйте содержимое папки обратно в ZIP и импортируйте.

Ненужное можно просто удалить: любая секция и любой файл необязательны, кроме
`name`. Убрали `images` — останется палитра, убрали `icons` — вернутся значки
приложения.

## Как поделиться

Параметры → Темы → долгое нажатие на карточку → «Поделиться». Приложение
соберёт ZIP с `theme.json` и всеми ресурсами.
